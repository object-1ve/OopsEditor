VS Code 文件拖拽实现架构

VS Code 的文件拖拽是一个 三层架构，从底层到业务层依次为：

1. 底层：ListView 拖拽基础设施

▎ 文件：src/vs/base/browser/ui/list/listView.ts

核心数据结构：

- NativeDragAndDropData — 处理来自操作系统原生的拖拽（如从文件管理器拖入），从 DataTransfer 中提取文件列表
- ElementsDragAndDropData<T> — 封
- ExternalElementsDragAndDropData<T> — 跨列表拖拽的共享数据
- StaticDND.CurrentDragAndDropDat同 ListView实例之间共享拖拽数据的通道

ListViewTargetSector 枚举定义了放置位置：

┌──────────┐
│  TOP     │  [0%-25%)
├──────────┤
│ CTR_TOP  │  [25%-50%)
├──────────┤
│ CTR_BTM  │  [50%-75%)
├──────────┤
│  BOTTOM  │  [75%-100%)
└──────────┘

拖拽生命周期：
- onDragStart → 设置 effectAllowed，调用 getDragElements，设置拖拽图片，存入 StaticDND
- onDragOver → 调用 dnd.onDragOve类做视觉提示，自动滚动（拖到顶部/底部边缘时列表自动滚动）
- onDrop → 清除视觉反馈，调用 dnd
- onDragLeave → 使用 100ms 延迟 防止闪烁

---
2. 中间层：AsyncDataTree 适配器

▎ 文件：src/vs/base/browser/ui/tr

由于 VS Code 的树是异步加载的（节点有展开/折叠状态），需要一个适配层：

用户实现的 ITreeDragAndDrop<T>
         ↑ 包装
AsyncDataTreeNodeListDragAndDrop<TInput, T>
         ↑ 适配
IListDragAndDrop<IAsyncDataTreeNode<TInput, T>>

这个适配器的工作是：把异步数据树 解包为实际元素 T，再传递给上层的DnD 实现。

---

▎ 文件：src/vs/workbench/contrib/iewer.ts

这是文件资源管理器的实际拖拽逻辑 erItem> 接口。

内部拖拽的详细流程：

handleExplorerDrop
  ├─ 展开折叠的子项，去重（distinctParents）
  ├─ 可选：弹出确认对话框（explorer.confirmDragAndDrop 配置）
  ├─ 根文件夹重排序 → doHandleRootDrop
  │    → workspaceEditingService.updateFolders()
  ├─ 复制操作 → doHandleExplorerD
  │    → ResourceFileEdit({ copy: true })
  └─ 移动操作 → doHandleExplorerD
       → 处理 FILE_MOVE_CONFLICT（覆盖确认）                  
压缩文件夹的特殊处理：                                        
VS Code 支持"压缩"显示连续空文件夹（如 src/utils/helpers 显示为一个整体）。拖拽时通过 getCompressedStatFromDragEvent 利用 document.elementFromPoint 检测用户拖到了压缩文件夹的哪个段  / data-icon-label-index DOM属性定位到正确的 ExplorerItem。

---
4. 跨窗口拖拽

onDragStart 中会调用 fillEditorsD 拽可以在 VS Code窗口之间工作。通过 CodeDataTransfers.FILES（JSON 格式的文件路径列表）实现跨窗口传递。
